```swift
/// Sentinel: stored as TimeInterval; 0 (or absent) maps to nil.
/// @Published so SettingsView re-renders when the value updates after a successful test.
@Published var lastConnectionTestAt: Date? {
    didSet {
        if let d = lastConnectionTestAt {
            UserDefaults.standard.set(d.timeIntervalSince1970, forKey: "last_connection_test_at")
        } else {
            UserDefaults.standard.removeObject(forKey: "last_connection_test_at")
        }
    }
}
```

Update `private init()` (currently lines 36-39):

```swift
private init() {
    let raw = UserDefaults.standard.string(forKey: "applescript_permission") ?? PermissionStatus.unknown.rawValue
    self.applescriptPermission = PermissionStatus(rawValue: raw) ?? .unknown
    let ti = UserDefaults.standard.double(forKey: "last_connection_test_at")
    self.lastConnectionTestAt = ti > 0 ? Date(timeIntervalSince1970: ti) : nil
}
```

**Why TimeInterval-backed Double instead of @AppStorage** — `Date?` has no native @AppStorage conformance (RawRepresentable wrappers are awkward). The existing applescriptPermission uses the same pattern; Phase 3 mirrors it for consistency.

**Why `> 0` and not `!= 0`** — Foundation `UserDefaults.double(forKey:)` returns 0 when the key is absent (no error). 1970 epoch is way before any plausible test date, so `> 0` is the cleanest sentinel.

**No save() change to existing logic** — applescriptPermission's didSet is unchanged. The two @Published variables are independent.

```swift
private func runConnectionTest() async {
    let result = await AppleScriptHelper.shared.testConnection()
    await MainActor.run {
        connectionTestResult = result
        connectionTestResultAt = Date()

        // .ok → persist last-success time. Other branches do NOT update persisted state.
        if case .ok = result {
            store.lastConnectionTestAt = Date()
        }

        // .permissionDenied → auto-deep-link (D3-16 deny path). User has button + banner + deep-link all visible.
        if case .permissionDenied = result {
            PermissionDeepLink.openAutomationPreferences()
        }

        // 5s auto-hide.
        hideResultTask?.cancel()
        hideResultTask = Task {
            try? await Task.sleep(nanoseconds: 5 * 1_000_000_000)
            await MainActor.run { connectionTestResult = nil }
        }
    }
}

private func hhmm(_ date: Date) -> String {
    let f = DateFormatter()
    f.dateFormat = "HH:mm"
    return f.string(from: date)
}
```

**Why a generic switch case for missing/timeout/otherError** — testConnection is contractually only ever supposed to return `.ok / .iTermNotRunning / .permissionDenied`. But the type is JumpResult (6 cases) and Swift's switch must be exhaustive. Defensive fallback to "not running" preserves UI invariants if the actor surface ever changes.

**Why no `if case .denied =` short-circuit before opening the deep-link** — D3-16 specifies that `.denied` triggers BOTH the visible label AND the deep-link. The visible label tells the user "Automation permission denied"; the deep-link opens System Settings. PermissionBannerView (already in repo) is the persistent surface; the SET-05 inline label is the click-time feedback.
