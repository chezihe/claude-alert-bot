# Phase 2 — UI Design Contract (Alert Loop)

> Visual and interaction contract for the floating alert widget, hover popover, and Settings window introduced in Phase 2. Generated by gsd-ui-researcher; verified downstream by gsd-ui-checker / gsd-ui-auditor.
>
> Platform note: this app is a native macOS utility, not a web app. The standard 60/30/10 web-style color contract and shadcn/Tailwind concepts do not apply directly — this spec uses macOS system materials, semantic system colors, and SF Symbols as the equivalent contract. Sections preserve the template's six dimensions; values are translated to AppKit/SwiftUI primitives.

## Spacing Scale

Declared values (multiples of 4, expressed in `pt` for AppKit/SwiftUI):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon-to-badge inset; popover row internal vertical padding |
| sm | 8pt | Popover row horizontal padding; Settings inline gaps; gap between widget icon and +N badge edge |
| md | 16pt | Widget screen-edge inset (top/right default); Settings form section padding; popover content padding |
| lg | 24pt | Settings form group spacing; permission banner internal padding |
| xl | 32pt | Settings window outer top/bottom padding |
| 2xl | 48pt | Reserved (not used in Phase 2) |
| 3xl | 64pt | Reserved (not used in Phase 2) |

Exceptions:
- **Widget icon hit-target: 36pt × 36pt minimum** (deliberate — exceeds 32pt grid because click target must be comfortable on Retina). Source: D2-04, native macOS menulet sizing convention.
- **Popover row min height: 36pt** to keep mouse hover comfortable. Multiple of 4 ✓.
- **+N badge: 16pt × 16pt** circle anchored at `(top: -4pt, trailing: -4pt)` of widget icon (slight overhang is intentional, matches macOS app-icon-badge convention).

## Typography

All sizes use the macOS system font (SF Pro). Phase 2 uses 4 sizes and 2 weights.

| Role | Size | Weight | Line Height | Used In |
|------|------|--------|-------------|---------|
| Body | 13pt | regular (400) | 1.4 (`NSFont` default) | Settings form labels, popover row project name |
| Label | 11pt | regular (400) | 1.3 | Popover row time suffix, "Clear all" button, Settings caption text, banner body |
| Heading | 13pt | semibold (600) | 1.3 | Settings section headers (`Section` header default), banner headline |
| Display | 11pt | semibold (600) | 1.0 | +N badge numeral (centered in 16pt × 16pt circle) |

Notes:
- All text uses dynamic system colors (`labelColor`, `secondaryLabelColor`) — never hard-coded hex — so dark mode is automatic.
- `secondaryLabelColor` reserved for: caption-style strings (popover time suffix, banner body, Settings stepper unit "초").
- `tertiaryLabelColor` not used in Phase 2.
- No custom fonts. No external font files.

## Color

macOS-native color contract. The web-style 60/30/10 dominant/secondary/accent split maps to: **system materials (60%) + system labels (30%) + system accent (10%)**, all dynamic to respect user's appearance + accent preferences.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) — surfaces | `NSVisualEffectView` material `.hudWindow` (widget) and `.thinMaterial` (popover), system Settings window background | All panel/popover/settings backgrounds |
| Secondary (30%) — content | `NSColor.labelColor` (primary text), `NSColor.secondaryLabelColor` (captions), system control fills (Toggle, Stepper, Picker default chrome) | All foreground text and standard system controls |
| Accent (10%) — emphasis | `NSColor.controlAccentColor` (system accent — user-selectable in System Settings) | Widget SF Symbol tint; popover row hover background (12% alpha); Settings "테스트 알림 보내기" button (`.borderedProminent` adopts accent automatically); focused control rings |
| Alert / warning | `NSColor.systemYellow` | Permission banner background tint (12% alpha) + stroke (40% alpha) + icon |
| Destructive | `NSColor.systemRed` | +N badge background (informational urgency only — no destructive actions ship in Phase 2) |

**Accent reserved for** (explicit list — must NOT spread to other elements):
1. Widget icon glyph tint
2. Popover row hover-state background (12% alpha)
3. Settings "테스트 알림 보내기" primary button
4. Standard system control focus rings (automatic via SwiftUI)

**Destructive actions in Phase 2:** none. "모두 지우기" (Clear all) is non-destructive (it dismisses pending alerts; the underlying Stop events stay in OSLog and sessions.json history is not affected). No confirmation modal.

**Dark mode:** automatic via dynamic system colors. No separate palette needed. The `.hudWindow` and `.thinMaterial` materials adapt automatically.

## Information Hierarchy

Single-glance priority order on the widget + popover surface:

1. **위젯 아이콘 (가장 큰 시그널)** — 사용자가 눈으로 즉시 인지. accent tint로 다른 화면 요소와 분리.
2. **+N 배지 (보조 시그널)** — N≥2일 때만 등장. systemRed로 시선 끌기.
3. **Hover popover row의 프로젝트명** — 사용자가 hover로 의도적으로 들여다볼 때만 노출.
4. **시각 보조 정보 (시각 라벨, ?, "Clear all")** — secondaryLabelColor + 11pt로 의도적으로 약화.

이 순서는 PROJECT.md Core Value("어느 세션 것인지 헷갈리는 순간 가치가 무너진다")의 직접 구현 — 헷갈림은 시각적 평준화에서 옴. 위계가 또렷해야 함.

## State Inventory

Each state must be implemented + verifiable.

### Widget states

| State | Trigger | Visual |
|-------|---------|--------|
| Hidden | 큐가 비어있음 | NSPanel `orderOut(nil)` — invisible |
