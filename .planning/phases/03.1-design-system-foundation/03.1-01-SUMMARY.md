# Phase 03.1 Plan 01: Design Tokens Module Summary

**One-liner:** `App/DesignTokens.swift` ships ColorTokens / GeometryTokens / MotionTokens namespaces — single source of truth for every SPEC.md §3 + §4 visual/motion value, drift-guarded by 15 XCTests; Wave 2 view refactors can now consume tokens directly without inline literals.

## Objective Achieved

- SC#1: A single Swift module exposes accent / status / popover geometry / motion tokens — `App/DesignTokens.swift` (65 LoC, three `enum` namespaces).
- SC#2: Drift-guard XCTests fail when any documented token value is mutated — 15 cases in `ClaudeAlertBotTests/DesignTokensTests.swift`, all pass on first GREEN run.
- SC#3: Motion tokens own the reduce-motion gate via `MotionTokens.bounceAnimation(reduceMotion: Bool) -> Animation?` factory.
- SC#5: Token module is consumable by Phase 4 multi-session views without modification — public surface frozen below.

## Findings (preserved verbatim from §design_decisions for downstream Plan 05 SUMMARY consolidation)

### F-1 — Drift: SPEC.md §3 says 270pt, code uses 280pt for popover width
Constraint D (visual indistinguishable) takes precedence — token value = `280` (code SoT). SPEC.md update is out-of-scope; filed as v1 follow-up. Drift-guard test asserts 280, not 270.

> Reconciliation note: at planning time the SPEC was already updated in commit `a8f9a96 docs(03.1): reconcile SPEC.md §3 popover width 270 → 280pt (F-1)`. The drift between SPEC and code is therefore historically resolved; the test still pins 280 as the active SoT.

### F-2 — Out-of-scope literals (DO NOT tokenise in this phase)

These have no SPEC.md §3/§4 row and stay as inline literals in Wave 2 with `// non-SPEC literal — see 03.1-SUMMARY.md F-2` annotation:

- `WidgetIconView` floating-widget-specific: `36/44pt` glyph frame, `16pt` badge, `-4/-4` overhang, `Color(NSColor.systemRed)` badge fill, `11pt` badge font, "Claude 작업 완료 알림. 보류 중 \(N)건" copy. Rationale: SPEC §3 widget row describes a different topology (NSStatusItem 22pt-in-28pt + `top: -11, right: -5` badge). Our floating NSPanel widget is a different component — keep its current literals literal.
- `PopoverRowView` row-hover: `Color(NSColor.controlAccentColor).opacity(0.12)` + `easeInOut(duration: 0.12)`. Rationale: SPEC §3 row-hover uses `rgba(217,119,87,0.13)` (accent-tinted) but our code uses system accent. SPEC §4 has no hover-animation row. Keep current behaviour; tokenisation happens in Phase 4 polish.
- `PopoverRowView` 도리도리/missing animation literals: `0.15s × 2`, `12°`, `0.4s` collapse, `0.2s` reduce-motion fallback. Phase 3 D3-11 lock; SPEC §4 has no entry. Keep as Phase 3 contract.
- `PopoverRowView` typography literals: `13pt` row body, `11pt` time suffix / `?` indicator. SPEC §3 typography section lists these but not as call-sites bound to this view's structure; treated as Phase 4+ polish.

### F-3 — `accent` token has zero existing call-sites in current code
Tokens defined for Phase 4 readiness (SC#5). Drift-guard test still asserts the token value, but no Wave 2 plan asserts `grep 0` against `D97757` (literal never existed in code).
