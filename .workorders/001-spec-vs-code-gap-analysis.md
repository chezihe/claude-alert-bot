# WO-001: SPEC.md vs `App/` 코드 갭 분석 → BACKLOG.md 산출

## Goal
현재 `App/` 디렉터리의 Swift 구현 상태를 `SPEC.md`의 모든 절(1~8)과 비교해, **남은 작업을 한 줄씩 나열한 `.workorders/BACKLOG.md` 파일**을 산출한다. 코드 수정은 없음 — **순수 진단 + 문서 1개 작성**이다.

## Context

이 프로젝트(Claude Alert Bot, macOS native, Swift/SwiftUI + AppKit)는 phase-03.1 popover refactor + visual fidelity manual checkpoint까지 완료된 상태다. 다음 작업을 분해하기 전에 SPEC 잔여 항목을 먼저 정리해야 한다.

`SPEC.md`는 다음 8절로 구성:
1. App Architecture (NSStatusItem, NSPopover, NSVisualEffectView 등 매핑)
2. iTerm2 Integration (Python API + IPC payload + 세션 jump)
3. Visual Tokens (color/geometry/typography)
4. Motion (10개 애니메이션 타이밍·커브 표)
5. State Model (`Session`, `AlertBotStore`, behaviors: onboarding/aging/grouping/mute/pin/quiet hours/clear-all)
6. Files to Build (목표 파일 트리)
7. Out of Scope (프로토타입 한정 demo 요소들)
8. Recommended Build Order (1~7 단계)

`App/` 현재 파일 (30개):
```
AppDelegate.swift, AppleScriptHelper.swift, ClaudeAlertBotApp.swift,
DesignTokens.swift, FloatingWidgetPanel.swift, FloatingWidgetWindowController.swift,
HookEvent.swift, HookListener.swift, ITerm2Jumper.swift, iTermSessionID.swift,
NotificationOrchestrator.swift, PermissionBannerView.swift, PermissionDeepLink.swift,
PopoverContentView.swift, PopoverRowView.swift, ProjectName.swift,
SessionGCTimer.swift, SessionRecord.swift, SessionRegistry.swift, SessionStore.swift,
SettingsStore.swift, SettingsView.swift, SocketPaths.swift, SoundPlayer.swift,
TerminalJumper.swift, WakeObserver.swift, WidgetIconView.swift,
WidgetPopoverController.swift, WorkspaceFrontmostObserver.swift
```

(SPEC.md 6절의 목표 트리는 `AlertBot/Views/`, `Models/`, `Services/` 같은 하위 디렉터리를 제안하지만, 실제 구현은 평탄한 `App/` 구조다. **이 트리 차이는 갭으로 보고하지 말 것** — naming convention 차이일 뿐 기능 갭 아님.)

## Constraints

- **NO CODE CHANGES**: Swift 파일 수정·생성 금지. 산출물은 `.workorders/BACKLOG.md` 파일 1개뿐.
- CLAUDE.md "No Over-Editing" 준수
- macOS 14 타깃, Swift 5.10+, ad-hoc 서명, Sandbox 안 씀 (참고용 — 이 WO는 코드 안 건드림)
- If you cannot read external files (SPEC.md / App/*.swift / CLAUDE.md), **say so explicitly in the deviations note** instead of guessing. 이 경우 반쪽짜리 BACKLOG라도 작성하고 어디까지 봤는지 명시.
- 분석 깊이는 **함수 시그니처 / SwiftUI 뷰 본문 / 주석** 정도까지만. 한 줄씩 정확히 매핑하려고 코드를 한 줄씩 다 따라갈 필요 없음.
- 결과 매핑이 모호하면 `[UNCLEAR]` 태그 + 보충 1줄. 추측해서 [DONE]/[TODO] 단정하지 말 것.
