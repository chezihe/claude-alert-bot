## Reduce-Motion Path

End-to-end gate confirmed:

1. **SwiftUI Environment read** (`App/WidgetIconView.swift:12`):
   ```swift
   @Environment(\.accessibilityReduceMotion) private var reduceMotion
   ```
2. **Call-site bridge** (`App/WidgetIconView.swift:26`):
   ```swift
   guard let anim = MotionTokens.bounceAnimation(reduceMotion: reduceMotion) else { return }
   ```
3. **Token factory** (`App/DesignTokens.swift:57-60`):
   ```swift
   static func bounceAnimation(reduceMotion: Bool) -> Animation? {
       guard !reduceMotion else { return nil }
       return .easeInOut(duration: bounceDuration).repeatForever(autoreverses: true)
   }
   ```

When reduce-motion is **on**, the factory returns `nil` → the `guard let` early-returns → `bounceOffset` stays at `0` and no animation is registered. Behaviorally equivalent to the previous `guard !reduceMotion else { return }`. SC#3 (uniform reduce-motion gate via MotionTokens factory) landed for the widget — Plan 03 will repeat this pattern for `PopoverContentView` (NSWorkspace path).
